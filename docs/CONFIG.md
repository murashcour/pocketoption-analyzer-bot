# Настройки (config.json)

Все настройки бота хранятся в файле config.json. При первом запуске
он создаётся автоматически с дефолтными значениями. При запуске
бот показывает интерактивное меню для изменения параметров.

## Основные

| Параметр | Дефолт | Описание |
|---|---|---|
| expiration | 60 | Экспирация сделки в секундах |
| check_interval_sec | 15 | Интервал проверок в серии (сек) |
| max_checks | 4 | Макс. количество ступеней в серии |

## Ставки

| Параметр | Дефолт | Описание |
|---|---|---|
| base_percent | 1.0 | Базовый процент от баланса (1%) |
| min_balance_for_percent | 100 | Порог баланса для режима процентов |
| fixed_steps | [1, 2, 4, 8] | Фиксированные ступени при малом балансе |

Как работает:

- Баланс >= 100 → 1-я ставка = 1% от баланса, дальше ×2
- Баланс < 100 → фиксированные 1, 2, 4, 8 долларов

Пример при балансе 150:

- 1-я ступень: 1.50
- 2-я ступень: 3.00 (1.50 × 2)
- 3-я ступень: 6.00 (3.00 × 2)
- 4-я ступень: 12.00 (6.00 × 2)

|---|---|---|

| payout_max_otc | 92 | Максимальный payout OTC (%) |

### Real

| Параметр | Дефолт | Описание |
|---|---|---|
| payout_min_real | 75 | Минимальный payout Real (%) |
| payout_max_real | 92 | Максимальный payout Real (%) |

### Общие

| Параметр | Дефолт | Описание |
|---|---|---|
| payout_recheck_sec | 1800 | Перепроверка payout (сек) |

Пары с payout вне диапазона не торгуются.

**Почему разные диапазоны:**
- OTC — синтетические, payout выше (85-92%)
- Real — реальный рынок, payout ниже (75-92%)

## Real-пары

| Параметр | Дефолт | Описание |
|---|---|---|
| include_real | True | Включать Real-пары |
| real_asset_types | ["currency"] | Типы Real (только Currency) |
| timezone | "Europe/Moscow" | Часовой пояс для проверки Forex |
| forex_trade_days | [0, 1, 2, 3, 4] | Дни Forex (0=Пн, 4=Пт) |

**Логика:**
- Real-пары — только **Currency** (форекс), крипта исключена
- Real-пары не торгуются в выходные (Forex закрыт Сб-Вс)
- Проверка дня недели — по `timezone` (МСК)

**Параметры `forex_trade_days`:**
- `0` = Понедельник
- `1` = Вторник
- `2` = Среда
- `3` = Четверг
- `4` = Пятница
- `5` = Суббота (не рекомендуется)
- `6` = Воскресенье (не рекомендуется)

## Защита от просадки

| Параметр | Дефолт | Описание |
|---|---|---|
| max_drawdown_percent | 30 | % просадки для срабатывания |
| drawdown_pause_sec | 1800 | Пауза при просадке (сек) |
| drawdown_max_count | 2 | Макс. просадок до СТОП |

**Логика:**
- Старт: `reference_balance = initial_balance`
- Если `current < reference * (1 - percent/100)`:
  - `drawdown_count += 1`
  - Если `count >= max_count` → **СТОП** (ждём реакции)
  - Иначе → **пауза** → `reference = current` → **продолжить**

**Режимы:**
- `count = 1` → СТОП после 1-й просадки (без паузы)
- `count = 2` → пауза после 1-й, СТОП после 2-й (по умолчанию)

**Пример:**

Старт: $100, 30%, count=2
Просадка до $70 → пауза 30 мин → reference=$70
Просадка до $49 → СТОП


## Новости (TradingView)

| Параметр | Дефолт | Описание |
|---|---|---|
| news_enabled | True | Включить паузу при новостях |
| news_importance_min | 2 | Мин. важность (2=Medium, 3=High) |
| news_pre_pause_min | 10 | Пауза за N мин до новости |
| news_post_pause_min | 20 | Пауза N мин после новости |
| news_currencies | ["USD", "EUR", "GBP", "JPY"] | Валюты новостей |
| news_refresh_hours | 4 | Обновление календаря (часы) |
| news_fallback_stop | True | СТОП, если календарь не загружен |

**Источник:** `https://economic-calendar.tradingview.com/events` (бесплатно).

**Логика:**
- Календарь загружается при старте и обновляется каждые 4 часа
- Перед сделкой проверяется: не попадаем ли в окно новости
- Если новость — пауза до конца окна (post_pause)

**Важность:**
- `1` = Low (не блокирует)
- `2` = Medium (блокирует при `news_importance_min=2`)
- `3` = High (блокирует всегда, если `importance_min<=3`)

**Fallback:**
- Если календарь не загрузился и `news_fallback_stop=True` → **СТОП**
- Если `False` → **торговать без паузы** (не рекомендуется)

## Управление пропусками

| Параметр | Дефолт | Описание |
|---|---|---|
| skip_before_change_plus | 5 | Пропусков после плюсовой серии |
| skip_before_change_minus | 1 | Пропусков после минусовой серии |

Логика:

- После плюсовой серии — 5 пропусков на паре, потом смена
- После минусовой серии — 1 пропуск, потом смена
- После смены пары — лимит сбрасывается на 1

## Как изменить настройки

### Способ 1: через интерактивное меню (рекомендуется)

При запуске бот показывает меню:

    ТЕКУЩИЕ НАСТРОЙКИ
    [1]  expiration              = 60
    [2]  min_confirmations       = 3
    ...

    Номер — изменить
    Enter — торговать
    r — сброс на дефолты
    q — выход

Введи номер — измени параметр. Enter — запустить торговлю.

### Способ 2: вручную в config.json

    vim config.json

Найди нужный параметр, измени, сохрани.

ВАЖНО: не запускай бота во время редактирования.

### Способ 3: сбросить на дефолты

Если что-то сломалось:

    rm config.json

При следующем запуске создастся новый с дефолтными значениями.

Или в меню бота нажми r.

## Где хранится config.json

Файл создаётся в папке проекта:

    ~/bot/config.json

В .gitignore он добавлен — не попадает в репозиторий. Это значит,
что твои настройки — только твои, они не публикуются в GitHub.

## Дефолтные настройки

Полный шаблон с дефолтами — в config.default.json. Если хочешь
начать с чистого листа — скопируй его:

    cp config.default.json config.json

## Безопасность

config.json НЕ содержит SSID — SSID передаётся через переменную
окружения PO_SSID. Это безопаснее.

Если ты случайно скоммитил config.json — он не критичен, там
только настройки бота, без секретов.
